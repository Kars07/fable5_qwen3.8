  ### 1. 🔍 Is the Dataset Correctly Configured for RL Training?                                                                                                                         
                                                                                                                                                                                         
  Yes. The dataset in  is formatted specifically for Reinforcement Learning from Verifiable Rewards (RLVR) and GRPO:                                                                     
                                                                                                                                                                                         
  1. State Transition Modeling (Sₜ):                                                                                                                                                     
      • Each sample is not an isolated prompt; it contains the complete conversational and terminal interaction buffer from Turn 0 up to Turn t.                                         
      • This ensures the model learns to read previous command errors, missing dependencies, or compilation outputs and conditions its next decision on real state transitions.          
  2. Trajectory-Aware Splitting (Zero Train/Val Leakage):                                                                                                                                
      • In standard SFT, splitting random rows can leak turns of the same task into both train and validation sets.                                                                      
      • In our converter (convert_rl.py), splitting is done by unique source_trajectory_uid. All turns of a trajectory stay exclusively in Train (29,485 records across 2,581            
      trajectories) or Holdout Val (1,626 records across 135 trajectories).                                                                                                              
  3. Pydantic Wire Integration:                                                                                                                                                          
      • taskset.py reads the converted JSONL directly, providing the prompt to the agent and feeding expected_answer_raw to the @reward scoring function.

  1. When running TerminalPivotTaskset (Single-Step RLVR):                                                                                                                               
      • The infrastructure does not need E2B. The prompt history is already captured in the dataset, and the model's generated decision is scored immediately by the task verifier. This

  2. When running Harbor Terminal-Bench 2.0 Evaluation (evaluate_harbor_e2b):                                                                                                            
      • E2B is used automatically. The runner contacts E2B, launches a dedicated Linux microVM, installs the environment/harness inside the microVM, runs the multi-turn session, runs   
      the verifier test suite inside the microVM, and tears it down.

  ### 4. 🔄 End-to-End GRPO Reinforcement Learning Flow                                                                                                                                  
                                                                                                                                                                                         
  Here is the exact cycle that executes during an RL step:                                                                                                                               
                                                                                                                                                                                         
       1. SAMPLING PHASE (vLLM / Modal GPU)                                                                                                                                              
          Prompt: [System Instructions + Task Description + Past Terminal Buffer]                                                                                                        
          Model generates G=4 candidate completions:                                                                                                                                     
             Candidate 1: <think> ... </think> <tool_call>cat /app/config.json</tool_call>                                                                                               
             Candidate 2: <think> ... </think> <tool_call>grep -r "error" /var/log</tool_call>                                                                                           
             Candidate 3: <think> ... </think> <tool_call>ls -la /app</tool_call>                                                                                                        
             Candidate 4: <think> ... </think> Task complete.                                                                                                                            
                                                                                                                                                                                         
       2. VERIFICATION & REWARD COMPUTATION (@reward)                                                                                                                                    
          - Format Check: Does it have clean <think> tags? (+0.2)                                                                                                                        
          - Tool Check: Does it have valid <tool_call> syntax? (+0.4)                                                                                                                    
          - Action Match: Does it match the target command sequence? (+0.4)                                                                                                              
          Rewards: R = [1.0, 0.6, 0.4, 0.0]                                                                                                                                              
                                                                                                                                                                                         
       3. ADVANTAGE CALCULATION (Prime GRPO)                                                                                                                                             
          Mean Reward: μ = (1.0 + 0.6 + 0.4 + 0.0) / 4 = 0.5                                                                                                                             
          Advantages: A_i = R_i - μ  →  [+0.5, +0.1, -0.1, -0.5]                                                                                                                         
          (Notice: Positive advantages boost Candidates 1 & 2; negative suppress Candidates 3 & 4)                                                                                       
                                                                                                                                                                                         
       4. POLICY GRADIENT UPDATE (Trainer GPU)                                                                                                                                           
          Loss = - E [ (π_θ / π_ref) * A_i - β * KL(π_θ || π_ref) ]                                                                                                                      
          Applies cosine learning rate schedule, updates LoRA weights, and saves checkpoints.
